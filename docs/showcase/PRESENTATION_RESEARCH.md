# Make the engineering result visible

Research date: 1 November 2026. This is a presentation study, not a compiler benchmark or a popularity explanation.

## Discovery and evidence

Fifteen GitHub repository searches sorted by stars (maximum40 per query), the user's named seeds and three primary-source/directory seeds produced **241 unique candidates**. **40** repositories received pinned README/tree/release inspection. The inventory includes every returned match; libraries, SCADA/runtime products, general orchestrators and unrelated matches are labelled separately. Metadata-only matches are not promoted to reviewed engineering tools. Search is bounded; this is not an exhaustive census of GitHub.

## Our observed presentation gaps and selected edits

Baseline: `9b209e1e559a726bdce12450c48af56b60ed6cc8`.

| Observation | Change in this task | Acceptance |
|---|---|---|
| The first executable example is IL↔MPU, while AX is described mainly as infrastructure. | Lead with the AX requirement→project→revision→build→evidence workflow and the actual neutral run result. | The first screen links the run, its inputs, status and reproduction path. |
| No tracked demonstration media in the baseline. | Original hero and evidence-linked short run summary; preserve a full sanitized record. | Every displayed stage agrees with actual records; rendered log animation is labelled. |
| Installation, vendor prerequisites and first prompt are separated. | Give two clear entry routes: native AX workflow on a prepared Windows host and the no-IDE file demo. | A reader can choose the correct route and find MCP+skill setup. |
| Historical blocked/native NOT_RUN records can be mistaken for the last word. | Add a dated new run and link the unchanged historical reports. | Do not replace historical results or claim stages the new run did not execute. |
| English/Turkish opening order and skill placement differ. | Match outcome, media, target table, first-task prompt and evidence links. | Same scope in both languages, About and campaign copy. |

We already have bilingual READMEs, topics, a release, a companion skill and a [Glama listing](https://glama.ai/mcp/servers/ufukefekaya-tr/delta-plc-agent). The change is making the result easier to see and try, not claiming we were absent from every directory.

## What the study does not establish

A popular project may have no GIF; a small project may have several. Stars alone do not explain distribution, code quality or customer adoption. Competitor private visit/clone data was not available. Native screenshots and release statements are the authors' evidence, not an independent execution by this study. No competitor media or code is copied into this showcase.

## Measurement

Keep a private, dated baseline of repository views, clones, release-asset downloads and referrers. Views/clones are GitHub's rolling-window aggregates; asset downloads count files, not people or installations. Do not sum daily unique counts or attribute every change to one post. Compare the next manually requested snapshot with this baseline and track concrete example attempts, external questions/issues and contributions. No automatic monitor or social publication is created by this task.
